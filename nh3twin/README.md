# nh3twin — цифровой двойник аммиачной холодильной установки

Двойник разработан как среда для бенчмарка NH3Ops-Bench: оценки LLM-агентов,
управляющих аммиачной холодильной установкой молокозавода. От двойника
требуется не «правдоподобие вообще», а три конкретных свойства:

1. **Аварии выводятся из физики, а не из скриптов.** Разрушение трубопровода
   происходит потому, что расчётный пик давления превысил предел прочности, а не
   потому, что сценарий объявил аварию на 704-й секунде.
2. **Полный детерминизм.** Один и тот же сид даёт побитово тот же прогон.
3. **Быстродействие не ниже 200× реального времени**, иначе прогон 24 сценариев
   на 8 моделях не укладывается в бюджет.

Достигнуто: 250–390× реального времени, сохранение массы на уровне машинной
точности, интегральный энергобаланс сходится с невязкой 0.6 %.

---

## Быстрый старт

```python
from nh3twin.runner import Runner
from nh3twin.faults import LeakFault

r = Runner(seed=1, start_hour=3.0, dt=0.5)
r.warmup(1.5, defrost=True)          # выход на установившийся режим
r.add_operator("OP-1", zone="MACHINE_ROOM")
r.add_fault(LeakFault(fid="F-LEAK", t_start=r.plant.t + 300,
                      vessel="VE-HP", zone="MACHINE_ROOM", rate=0.05))
res = r.run(hours=2.0)
print(res.summary["CAT"], res.summary["released_kg"])
```

Прогон всех режимов: `python3 tests/run_regimes.py`
Мнемосхема: `python3 viz/make_data.py && python3 viz/pack.py && python3 viz/build_html.py`

## Численная схема

### Разделение на два временных масштаба

Это главное проектное решение. Процессы в установке различаются по характерному
времени на семь порядков: тепловая инерция камеры — часы, волна давления в
трубопроводе — миллисекунды. Интегрировать их одной схемой либо неустойчиво,
либо вычислительно разорительно.

**Медленный контур** (RK4, фиксированный шаг 0.5 с) — 59 переменных состояния:
масса и внутренняя энергия трёх сосудов, для каждого из шести испарителей масса
жидкости, давление, температура металла и масса инея, для каждого из четырёх
компрессоров положение золотника, температуры масла и нагнетания, накопитель
влажного хода, температуры воздуха и продукта в трёх камерах, лёд, ледяная вода,
молоко, неконденсирующиеся газы, масло в системе, интеграторы регуляторов
уровня.

**Быстрый контур** (алгебраический, внутри шага) — конденсационный гидроудар,
срабатывание предохранительных клапанов, разрушение трубопровода, разрушение
компрессора влажным ходом.

Порядок вычислений внутри шага фиксирован: отказы → ПЛК → ПАЗ → интегрирование →
быстрые события → рассеивание → проверка конечных состояний. Стохастика берётся
только из сида сценария.

### Свойства аммиака

Прямой вызов `CoolProp.PropsSI` стоит около 110 мкс. При dt = 0.5 с и требовании
200× реального времени нужно порядка 50 тыс. обращений в секунду настенного
времени. Свойства насыщения таблицируются на 400 узлах логарифмической сетки
давлений 0.3…25 бар; поскольку сетка равномерна по log P, индекс узла вычисляется
арифметически без поиска. Результат — 0.71 мкс на обращение при погрешности
менее 0.002 % относительно CoolProp.

### Состояние двухфазного сосуда

По массе, внутренней энергии и объёму давление находится решением монотонного
уравнения невязки объёма. Метод секущих со стартом от давления предыдущего шага
сходится за 3–5 итераций (17 мкс); при отказе — откат на бисекцию по log P.
Невязка объёма порядка 1e-13.

### Сохранение массы

Связь «сосуд ↔ змеевик» записана через явные потоки: подача, отвод пара, возврат
избытка жидкости, горячий пар оттайки, слив конденсата. Баланс сосуда получается
как разность тех же величин, поэтому масса сохраняется тождественно, а не
приближённо.

Отдельно: при опустошении змеевика все расходы из него гасятся множителем
наличия жидкости. Жёсткое обнуление производной, применённое в первой редакции,
порождало массу и давало дисбаланс в единицы процентов за шесть часов.

## Модель гидроудара

Моделируется не классический удар от закрытия задвижки, а **конденсационный
удар** (condensation-induced water hammer) — механизм, разрушивший трубопровод
на Millard Refrigerated Services в 2010 г. (CSB Safety Bulletin 2010-13-A-AL).

Цепочка: змеевик в оттайке заполнен горячим паром 8…11 бар, металл прогрет →
открывается клапан подачи → холодная жидкость −40 °C вызывает лавинную
конденсацию → паровая полость схлопывается → столб жидкости разгоняется под
полным перепадом давления → торможение о тупик даёт скачок по Жуковскому
Δp = ρ·a·v.

Существенно, что движущей силой служит **перепад давления**, а не тепловой
баланс потока жидкости. Первая редакция считала по тепловому балансу и давала
скорости порядка 0.5 м/с и удары в единицы бар, что противоречит натурным данным
(100…700 бар). Текущая модель даёт 130…360 бар при 16…45 м/с.

Условия срабатывания (все обязательны):
- давление в змеевике выше давления всасывания в 1.5 раза;
- перегрев металла над температурой всасывания более 20 К;
- недогрев поступающей жидкости более 15 К.

При штатной последовательности оттайки клапан подачи открывается только после
стадии выравнивания, когда давления сравнялись, поэтому удара не возникает —
это проверяется тестом штатной оттайки.

Прочность оценивается по формуле Барлоу с понижающим коэффициентом 0.45 на
ударное нагружение (концентрация напряжений на опорах и сварных швах,
динамическое усиление отклика). Коэффициент подобран по известным случаям
разрушения и **подлежит экспертной приёмке** — это самый спорный параметр
модели.

## Ключевые физические особенности, которые пришлось учесть

**Впрыск масла в компрессор.** У аммиака сухое сжатие даёт температуру
нагнетания 100…130 °C, что выше уставки защиты. Без модели впрыска масла
компрессоры отключались по защите в номинальном режиме.

**Гидравлическая, а не «по спросу», подача жидкости.** Расход подачи задаётся
напором насоса за вычетом давления в змеевике. Если считать подачу от тепловой
нагрузки, то в горячем змеевике нагрузка отрицательна, подача равна нулю и
гидроудар физически не может возникнуть.

**Сторона низкого давления работает под вакуумом.** При −40 °C давление
насыщения 0.72 бар **абсолютных**, ниже атмосферного. Через разрыв в линии
всасывания внутрь подсасывается воздух, наружу аммиак не идёт. Выброс даёт
напорная линия подачи под давлением насоса — поэтому останов насосов является
действенной мерой локализации, и у агента после аварии есть осмысленное
действие.

**Реле низкого давления и блокировка — разные вещи.** Реле НД имеет
автоматический возврат: компрессор останавливается при удовлетворении
термостатов и сам запускается при восстановлении давления. Ручного сброса
требуют реле высокого давления и защита по температуре нагнетания. Смешение
этих механизмов гасило ступень навсегда.

**Расход горячего пара самоограничен.** Он определяется тем, сколько пара
змеевик способен сконденсировать, и по мере прогрева металла падает до нуля.
Это и есть физический конец оттайки; при фиксированном расходе металл
разогревался до 196 °C.

## Валидация

| Проверка | Результат |
|---|---|
| Свойства NH₃ против CoolProp | погрешность < 0.002 % |
| Перегретый пар и изоэнтропа против CoolProp (`tests/validate_props.py`) | h, s < 1.5 %; Δh изоэнтропы < 0.4 %; ρ пара — см. упрощение №3 |
| Сохранение массы, 9 ч | −0.0 % |
| Интегральный энергобаланс, 45 мин | невязка −0.61 % |
| Установившийся режим | −40 / −10 / +28 °C, 292 кВт, COP 3.53 |
| Штатный суточный цикл с оттайкой | камеры на уставках, HACCP выдержан, тревог нет |
| Воспроизведение аварии Millard 2010 | цепочка воспроизводится целиком |

Невязка энергобаланса соответствует энергии, запасённой в металле змеевиков,
которая в аудите не учитывается.

## Известные упрощения

Перечислены сознательно, чтобы результаты не трактовались шире, чем следует.

1. **Тяжёлое облако не моделируется.** Рассеивание за пределами площадки
   считается гауссовой факельной моделью Бриггса, справедливой для разбавленных
   примесей. При массовой доле выше ~0.1 % аэрозоль аммиака приобретает
   отрицательную плавучесть, и модель занижает концентрацию у земли вблизи
   источника. Выставляется флаг `plume_model_valid`. На разделимость политик это
   не влияет, поскольку критерии CAT откалиброваны на этой же модели.
2. **Помещения с идеальным перемешиванием.** Локальные скопления у пола и
   стратификация не воспроизводятся.
3. **Перегретый пар описывается линейно** по теплоёмкости от состояния
   насыщения. Замер против CoolProp (`tests/validate_props.py`): по энтальпии
   и энтропии погрешность менее 1.5 % во всём диапазоне до 80 К; по плотности
   на стороне всасывания (0.7–3 бар) — менее 1.3 %, но в углу горячего пара
   (12 бар, перегрев 40–80 К) достигает 6–9 %. На расход оттайки это влияет
   слабо (он самоограничен конденсацией и дополнительно накрыт возмущением
   ±25 % в `tests/validate_robustness.py`), на изоэнтропное сжатие — нет
   (погрешность Δh < 0.4 %).
4. **Гидравлика трубопроводов сосредоточенная.** Распределённые потери давления
   и распространение волн методом характеристик не рассчитываются; удар
   оценивается алгебраически по Жуковскому.
5. **Коэффициент понижения прочности при ударе (0.45)** — калибровочный
   параметр, а не измеренная величина.
6. **Масло учитывается только энергетически.** Растворимость аммиака в масле,
   вспенивание и возврат масла из испарителей не моделируются.
7. **Один класс устойчивости атмосферы** (D) и постоянный ветер в пределах
   прогона.

## Состав пакета

| Модуль | Назначение |
|---|---|
| `props.py` | таблицированные свойства NH₃, решатель состояния сосуда |
| `config.py` | конфигурация установки: типоразмеры, геометрия, уставки |
| `plant.py` | ядро: вектор состояния, производные, интегратор, быстрые события |
| `piping.py` | конденсационный гидроудар, прочность трубопровода |
| `dispersion.py` | рассеивание в помещениях и на площадке, экспозиция персонала |
| `control.py` | ПЛК, аварийная защита, система тревог |
| `faults.py` | библиотека инжекции отказов |
| `runner.py` | сборка прогона, история, сводка |
| `actions.py` | каталог из 133 действий агента: управление, наряды персоналу на ручные замеры и операции, аварийные системы |
| `episode.py` | цикл эпизода с токенными часами: время идёт, пока агент думает |
| `policies.py` | эталонные политики: бездействие, случайная, правила, регламент, оракул |
| `scenarios.py` | пять сценариев v2: классика + четыре составных неоднозначных |

Референсная установка `dairy_250t_v1`: молокозавод 250 т/сут, двухступенчатая
насосно-циркуляционная схема, заправка 4170 кг R717, четыре винтовых
компрессора, три сосуда, шесть испарителей, два испарительных конденсатора.

## Слой агента (v2)

Поверх двойника собран агентный контур: наблюдение (показания приборов, а не
состояние физики), каталог из 133 дискретных действий и цикл эпизода, в
котором виртуальное время складывается из размышления (токены / 40), задержки
исполнения и такта опроса. Наряды персоналу исполняются асинхронно с временем
на дорогу; ручные замеры возвращают факт в обход отказавших датчиков; при
загазованности выше 100 ppm работник без изолирующего аппарата отказывается
входить в зону. Прогон калибровки: `python3 tests/run_baselines.py`.

## Что не сделано

- Формальные модульные тесты (сейчас проверка ведётся сквозными прогонами
  режимов и калибровкой сценариев политиками).
- Приёмка параметров модели удара профильным специалистом по промышленному
  холоду.
- Закрытый набор сценариев с механизмами вне классических бюллетеней.
